# Roblox artifact and runtime background

Pinned source references explain format and VM assumptions. See [artifact contracts](formats.md) and [Player capture limits](adaptive-builds.md) for supported inputs and runtime checks.

## Architecture findings

1. **Representation and execution.** LocalScript, ModuleScript and Script are source-container instance classes. Script can run on the client when RunContext is Client (enum value 2); class alone is insufficient. ModuleScripts do not establish client/server use by themselves. Static classification must also consider ancestor services. Sources: [script locations](https://create.roblox.com/docs/scripting/locations), [RunContext values](https://create.roblox.com/docs/reference/engine/enums/RunContext).
2. **Visibility after joining.** Replicated executable code can be examined in principle even when disabled or never run. Server-only code in ServerStorage/ServerScriptService does not become client code. This is an architectural exposure statement, not a supported public source-download API. Source: [Roblox confidentiality and replication](https://create.roblox.com/docs/scripting/security/access-control).
3. **Offline files.** Studio exports place data as compact binary `.rbxl` or XML `.rbxlx`; model equivalents share the serialization family. These can contain Source text, so no decompilation is needed. Source: [official place files documentation](https://create.roblox.com/docs/projects/place-files).
4. **Serialization.** The community rbx-dom format specification describes binary version 0, INST/PROP/PRNT and shared strings, LZ4/ZSTD chunks, and Bytecode property type `0x1d`. XML uses ProtectedString for source. These are artifact formats, not a specification of the current network wire protocol or a guarantee that Player caches contain recoverable place files. Sources: [binary specification](https://github.com/rojo-rbx/rbx-dom/blob/7a6ca296e25ea4dddd44b08449ceac58ae5c2476/docs/binary.md), [XML specification](https://github.com/rojo-rbx/rbx-dom/blob/7a6ca296e25ea4dddd44b08449ceac58ae5c2476/docs/xml.md).
5. **Acquisition.** Metadata lookup and source artifact access are separate operations. See [official download](acquisition.md#official-download) for the supported CLI workflow and [Creator Hub configuration](https://create.roblox.com/docs/projects/configure-experiences) for Studio copy settings.
6. **Compiled forms.** Upstream Luau has versioned serialized bytecode, type-information revisions, instruction/prototype/constant data and optional debug information. Deployed Roblox artifacts may have additional encoding/signing/wrapping; upstream compiler output is not proof of deployed Player compatibility. This pipeline preserves unknown bytes and requires an established encoding profile. Sources: [bytecode definitions](https://github.com/luau-lang/luau/blob/f46d879e28302a430029304f7f6a162aed66f103/Common/include/Luau/Bytecode.h), [loader](https://github.com/luau-lang/luau/blob/f46d879e28302a430029304f7f6a162aed66f103/VM/src/lvmload.cpp).
7. **Loss through compilation.** Comments, formatting and full original type syntax are unavailable from runtime instructions. Variable/debug names and line data depend on compiler/debug settings. Optimization can eliminate or rewrite constructs, so regenerated structured source need not resemble the original and a recompile does not prove equivalent behavior. Sources: [compiler options](https://github.com/luau-lang/luau/blob/f46d879e28302a430029304f7f6a162aed66f103/Compiler/include/Luau/Compiler.h), and the authored O0/O1/O2 semantic fixtures.
8. **Runtime and memory.** Official heap tooling exposes allocations, object types and reference paths. Its documentation does not promise a full source or serialized-bytecode dump. Upstream VM Proto structures are build-specific in-memory objects; reconstructing them from a process snapshot differs from capturing a serialized buffer at the loader boundary. Sources: [memory/heap tooling](https://create.roblox.com/docs/studio/optimization/memory-usage), [VM object definitions](https://github.com/luau-lang/luau/blob/f46d879e28302a430029304f7f6a162aed66f103/VM/src/lobject.h).
9. **Incomplete observations.** Workspace streaming can load/unload content around replication foci. Runtime-created, conditionally replicated, per-player and destroyed/unparented objects need separate observation plans; a single client snapshot cannot establish game completeness. Source: [instance streaming](https://create.roblox.com/docs/workspace/streaming).

For build pins and native tooling, see the [native decompiler](decompiler.md). For authored checks and evidence scope, see [CFG verification](cfg-verification.md).
